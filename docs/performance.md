# Performance

All numbers come from release builds on the machine these were measured on (4-core Intel Xeon
@ 2.10 GHz, shared cloud VM, so expect ±30% between runs). They are for orientation; the CI checks
how costs *grow* with the document, not absolute times.

Documents are generated by `crates/gpui-editor-core/benches/common/mod.rs`: sections of 9 text
blocks (heading, paragraph with marks and a link, nested bullets, tasks, quote, paragraph).

## Core (criterion)

`cargo bench -p gpui-editor-core` (add `-- edit/` to run one group). Median time per operation:

| Operation | 100 blocks | 1,000 blocks | 5,000 blocks |
|---|---:|---:|---:|
| Parse JSON (`Node::from_json_str`) | 0.32 ms | 3.2 ms | 18.5 ms |
| Parse Markdown (`Node::from_markdown`) | 0.08 ms | 0.87 ms | 5.7 ms |
| Export JSON (`to_json_string`) | 0.25 ms | 2.2 ms | 20.2 ms |
| Export Markdown (`to_markdown`) | 0.10 ms | 0.68 ms | 4.3 ms |
| Export Markdown, TipTap flavor | 0.08 ms | 0.82 ms | 3.9 ms |
| Plain text (`plain_text`) | 5 µs | 49 µs | 0.87 ms |
| First keystroke (records an undo step) | 27 µs | 0.26 ms | 1.7 ms |
| Next keystroke (while typing) | 1.2 µs | 3.8 µs | 6.0 µs |
| Enter (`split_block`) | 31 µs | 0.29 ms | 1.5 ms |
| Backspace joining two blocks | 29 µs | 0.31 ms | 1.5 ms |
| Toggle bullet list | 30 µs | 0.29 ms | 1.9 ms |
| Undo + redo | 25 µs | 0.25 ms | 1.4 ms |
| Select all + delete | 62 µs | 0.46 ms | 3.4 ms |
| Move caret right + left | 1.7 µs | 1.6 µs | 2.3 µs |
| `block_text` of every block | 75 µs | 0.95 ms | 3.4 ms |

Operations that change the structure of the document (first keystroke, Enter, Backspace at a
block start, lists, undo) walk it once to record the undo step and rebuild the block index: they
are linear. Typing inside a block and moving the caret do not depend on the document size.

Before/after of the optimizations made with these benchmarks:

| Change | Measure | Before | After |
|---|---|---:|---:|
| Typing keeps the text block index | Next keystroke, 5,000 blocks | 555 µs | 6 µs |
| Undo steps share unchanged blocks | 100 undo + 100 redo, 1,800 blocks | 263 ms | 19 ms |
| Undo steps share unchanged blocks | 200 Enter, 1,800 blocks | 358 ms | 89 ms |
| Cached text block index | 2,000 caret moves, 1,800 blocks | 459 ms | 5 ms |

## Complexity guards (CI)

`cargo test -p gpui-editor-core --release --test scaling -- --nocapture --test-threads=1` times
each operation on 4,000 and 16,000 blocks (median of 7 trials) and fails if the ratio exceeds 10
for operations that may walk the document (linear measures ×4 to ×7 at these sizes, quadratic about
×16), or 3 for those that only touch the caret's block. Typical output:

| Operation | Ratio for 4× the blocks |
|---|---:|
| Parse JSON / Markdown | ×4.8 / ×4.2–5.6 |
| Export JSON / Markdown | ×4.2–4.5 / ×5.7 |
| First keystroke, Enter, Backspace join | ×3–5 |
| Toggle list, delete all, undo + redo | ×3.3–6.9 |
| Next keystroke, caret move, `block_text` of one block | ×0.9–1.2 |

Without the "typing keeps the text block index" change, the next-keystroke guard fails (×3.7).

## Editor component (GPUI)

`cargo test -p gpui-editor-ui --release --test perf -- --nocapture`. Each interaction is followed
by a full update, layout and paint (GPUI's test platform, no GPU):

| Blocks | Keystroke | Caret move | Ctrl+End, Ctrl+Home | Open `/` menu | Paste 50 lines |
|---:|---:|---:|---:|---:|---:|
| 100 | 2 ms | 1.6 ms | 3 ms | 3.8 ms | 6 ms |
| 500 | 9–10 ms | 9–10 ms | 17–20 ms | 20–23 ms | 17–20 ms |
| 2,000 | 42–65 ms | 45–60 ms | 80–130 ms | 90–115 ms | 78–127 ms |

The CI fails if a keystroke in a 4× larger document costs more than 10× as much (measured
×4–7.4).

Every frame lays out every block. Profiling (`perf`) shows GPUI's layout engine (Taffy) and the
element tree dominating; the editor's own work to build the tree is about 3 ms at 2,000 blocks.
Documents up to about 500 blocks stay within a 16 ms frame; beyond that, typing visibly lags.
Rendering only the visible blocks (virtualization) is the remaining improvement for long documents.
